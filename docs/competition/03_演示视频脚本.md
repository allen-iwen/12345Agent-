# 3–5 分钟演示视频脚本（复赛必交材料）

> 目标时长 4 分 30 秒（含片头片尾）。原则：**每条功能都配一个可验证的数字**，
> 不说"我们很智能"，只说"我们做到了什么、怎么证明"。

## 拍摄与录屏准备

| 项 | 要求 |
|---|---|
| 录屏分辨率 | 1920×1080（浏览器 100% 缩放，窗口最大化） |
| 演示环境 | 本地 `http://127.0.0.1:8000`（后端 + 前端已启动）；终端字号调到 16pt 以上 |
| 预置数据 | 案件队列保留 2–3 件不同状态案件；看板各列有卡片 |
| 演示账号 | RBAC 默认关闭（保证流畅）；如需展示权限，用「流转看板」顶部的操作身份切换 |
| 备用 | 提前录好一段完整链路（约 40 秒）作为卡顿时备用素材 |

## 分镜脚本

### 00:00–00:20　片头与定位（20s）

**画面**：应用首页（工作台）全景，鼠标轻扫顶栏三个导航（工作台 / 流转看板 / 知识库）。

**旁白**：
> "这是我们的 12345 热线工单智能体。大多数同类作品做的是「把诉求变成一份工单」；
> 我们做的是——**把单派对、把急件挑出来、把反复投诉的事管起来**。
> 每一条结论都能追溯到公开政策条款，每一次判断拿不准就交给人。"

**字幕**：受理 → 派单 → 答复 → 督办｜每条建议有依据 · 每个风险有时钟

---

### 00:20–01:20　案例一：录音受理 → 属地+部门双维派单（60s）

**画面**：
1. 左侧录入区点「现场录音」（或「录音文件」上传一段脱敏通话），显示"转写完成 · 讯飞云端 · x.x s / N 段"；
2. 点「生成工单」，展示五节点进度；
3. 出结果后，先展示 ①原始诉求卡（原文与整理稿可切换）→ ②标准化工单 → ③事项分类（候选与置信度）；
4. 滚到 ④承办单位卡，**重点展示**：`派单决策 · 属地主办` 徽标、主办单位、协办单位、**展开「派单依据链」**（政策依据 / 属地判定 / 职责依据 / 历史案例四条）。

**旁白**：
> "录音进来，讯飞云端双引擎转写并降噪整理，事实逐字保留。
> 五个节点依次给出工单、分类和转派建议。请注意这一栏——
> 派单不是让模型直接猜部门名，而是**规则锚定 + 模型复核**：
> 先按《安徽省12345热线诉求闭环办理工作规范》的「属地管理、分级负责」确定属地主办，
> 再由模型补充协办单位与理由，分歧会显式标记为需人工裁断。
> 这条依据链是可以逐条展开的。"

**字幕**：规则锚定 + 模型复核｜依据链可展开｜分歧交人工

---

### 01:20–02:00　案例二：现场照片 → 险种定级 → 特急（40s）

**画面**：
1. 回到录入区，点「现场照片」上传一张图（建议用 `data/eval/vision/real/manhole_missing_01.jpg`）；
2. 显示"图片分析：发现隐患 · 井盖缺失 · 特急 · …"与缩略图；
3. 补一句简短文字后生成工单；
4. 详情页展示 **急件分级横幅（特急 + 30 分钟内电话通知 + 24 小时内反馈进展）** 与 **现场照片证据卡**（隐患判定 / 严重程度 / 置信度 / 可见要素）。

**旁白**：
> "市民上传的现场照片也能作为证据：视觉模型判读隐患类型与严重程度。
> 这里有个我们特意做的设计——**不采用模型自报的严重程度，而是按险种定级**：
> 井盖缺失、电线坠落、消防通道堵塞一律进特急，因为实测发现模型的"程度打分"跨次不稳定，
> 而险种识别稳定在 93.8%、隐患有无 100%。政务实践也是按事项类型定级。"

**字幕**：按险种定级｜隐患类型 93.8%｜隐患有无 100%

---

### 02:00–02:40　答案把关：合规审查 + 时限督办（40s）

**画面**：
1. 滑到 ⑤答复草拟卡，展示 **答复合规审查** 区块（风险等级 + 问题清单 + 修改建议 + 政策依据）；
2. 展示 ⑤上方的 **办理时限条**（到期时刻 / 工作日模式 / 剩余时长 / 依据条款 / 备注）；
3. 切到「流转看板」页，展示顶部 **时限督办条**（正常/临期/超期分布 + 最紧迫案件）。

**旁白**：
> "答复不能随口承诺。我们按规范要求做了合规审查：过度承诺、承诺具体时限、隐私泄露、推诿表述等九类问题，
> 命中就给出修改建议和依据。清单里 20 条违规样本召回 100%、20 条合规样本零误报。
> 时限方面，急件 24 小时、一般件按工作日推进，临期和超期在看板上自动冒出来，超期直接附督办建议。"

**字幕**：违规召回 100% · 误报 0%｜临期/超期自动督办

---

### 02:40–03:30　流转看板与知识运营（50s）

**画面**：
1. 看板：拖动视线扫过 10 列状态；点一张卡片的「确认派单」按钮，卡片移动到「已派单」列；
2. 打开一张案件详情，展开「工单流转」条的**流转记录**（谁、何时、从哪到哪）；
3. 切到「知识库」页，展示 **知识词条** 面板：新建/修订/发布、修订历史；
4. 回到案件详情，若有「沉淀为词条」入口则演示一次（否则口头说明）。

**旁白**：
> "工单在系统里不是一张静态单据，而是一条有状态的流水线：已受理、已分类、已派单、签收、办理、回执、审核、归档，
> 每一步都有角色守卫，非法跳步会被拒绝，每次流转都记账——谁在什么时候把哪张单从哪推到哪。
> 右边的知识词条是「口径层」：办理经验、答话口径、案例复盘都能沉淀，发布后才生效。
> 案件定稿后可以一键把派单结论和答复口径沉淀成词条草稿，人工确认后发布——**越用越准**。"

**字幕**：15 条合法迁移 + 角色守卫｜口径层与依据层分工

---

### 03:30–04:10　可信性设计：指标与证据（40s）

**画面**：
1. 切到终端，依次跑（可加快放）：`python scripts/eval_dispatch.py`、`python scripts/verify_reply_audit.py`、`python scripts/eval_vision.py` 的关键输出行；
2. 回到 PPT 的「测试样本与测试结果」页（或屏幕贴出指标表）。

**旁白**：
> "最后是最关键的一点：这些结论不是我们自己说的。
> 派单策略用官方 18 条样例的历史实际承办单位做对照：通用做法按类别推部门只有 5.6% 命中，
> 我们的三层决策是 94.4%；分类留一验证 100%；图片隐患类型 93.8%；答复合规召回 100%、误报 0%。
> 每条结论都有脚本，评委在自己机器上可以重跑复现。"

**字幕**：派单 94.4% vs 通用 5.6%｜全部指标可复现

---

### 04:10–04:30　收尾与合规承诺（20s）

**画面**：回到首页全景，缓慢淡出。

**旁白**：
> "机器只出建议：不自动派单、不自动向群众发送任何内容，未经人工最终放行不得归档。
> 我们想让 12345 的每一位坐席，都能少花二十分钟在文书上，把时间留给真正需要人来判断的事。"

**字幕**：AI 仅作辅助 · 最终以工作人员审核为准

## 演示时容易翻车的点（提前规避）

| 风险 | 规避 |
|---|---|
| 真实链路耗时 30–60 秒 | 提前跑一次预热；生成中展示"五节点依次执行"文案，旁白同步解释；备用素材兜底 |
| 图片上传后视觉判读 3–6 秒 | 旁白覆盖等待时间（讲"按险种定级"的设计动机） |
| 局域网复核模型未开 | 默认关闭，无需现场演示；口头说明可开启与代价（30s → 110–137s） |
| Jev 未拿到 Key | 按「已实现、待启用」表述，展示契约与回退设计，不宣称已产出对比数据 |
| 数据里有大量历史测试案件 | 看板卡片前缀以"关于…"为主，无敏感信息；必要时提前清理测试案件 |

## 需要准备的三段素材

1. **完整链路录屏**（文本建单，约 40 秒）——备用
2. **图片受理片段**（上传 → 结论 → 特急）——正式片段
3. **看板迁移片段**（点确认派单 → 卡片移动）——正式片段
