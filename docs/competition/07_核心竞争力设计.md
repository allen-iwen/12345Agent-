# 核心竞争力设计 · 从"工单文书生成器"到"派单决策与诉求治理智能体"

> 团队：aiwen ｜ 赛题：12345 热线工单智能生成与转派辅助智能体 ｜ 复赛 2026-09-20 ~ 10-14
> 设计原则：**每条能力都必须有 ①真实业务痛点 ②公开政策依据 ③官方数据证据 ④可量化验证指标**

---

## 一、竞争格局判断：同质化在哪里

复赛 8 项必展示功能，绝大多数团队会用一条"直线式提示词链"实现：

```
输入文本 → LLM提取要素 → LLM生成工单 → LLM推类别 → LLM推部门名 → LLM写回复 → 输出
```

这样能"跑通"，但会被评委一眼看穿三个问题：

| 同质化做法 | 真实业务后果 |
|---|---|
| 按事项类别直接推市直部门（如"城市管理→城管局"） | **与芜湖实际派单逻辑不符**（见下方实测：命中率仅 5.6%），派错就要退回重派，正是热线最耗时的环节 |
| 不做紧急度判断 | 燃气泄漏、井盖缺失和"路灯不亮"走同一条流程排队 |
| 只处理单件工单 | 同一点位反复投诉、多人反映同一件事，系统看不见 |
| 结论不给依据 | 工作人员不敢用（政务场景"说不出依据的建议=不能用"） |

**我们的判断：工单文本生成只是入口，真正的价值在"派给谁、多急、会不会反复、怎么答不出事"。**

## 二、定位：派单决策与诉求治理智能体

> **一句话：别的智能体帮你"写工单"，我们帮你"把单派对、把急件挑出来、把反复投诉的事管起来"——每一条结论都可追溯到政策条款。**

三条支柱能力，全部有政策依据与数据证据（详见下）。

---

## 三、支柱一：属地+部门双维派单（派得对）★最硬的一条

### 业务痛点
12345 派单错误的代价是"退回—重新交办—再退回"，安徽省级规范甚至专门规定"承办单位不得随意退回工单，经 3 次交办仍无法确定责任主体的由热线直接指定"——**说明派错部门是高频顽疾**。

### 政策依据（《安徽省12345热线诉求闭环办理工作规范》2025-04 印发）
- 转办遵循「**属地管理、分级负责**」原则；
- 对权责清晰的事项**可直接转至具体承办单位，同时抄送属地 12345 热线主管部门督促协调**；
- 涉及诉讼、仲裁等法定途径的，明确告知诉求人相应渠道。

### 数据证据（官方 18 条样例工单的历史实际办理单位）

| 策略 | 主办单位命中率 |
|---|---|
| 通用做法：按事项类别推市直部门 | **5.6%**（1/18） |
| 属地优先（区划识别 → 属地政府/开发区） | 83.3%（15/18） |
| **本方案：三层决策（专业直派 → 属地主办 → 类别兜底）** | **94.4%**（17/18） |

历史实际派单结构：**属地政府/开发区 16/18 = 89%**，市直部门仅 2/18 = 11%。
（复现脚本：`backend/scripts/eval_dispatch.py`；样本 18 条，用于方法对比验证。）

**已知边界（诚实标注）**：剩余 1 例为"市级消费维权专业渠道直派"（实际由 12315 中心办理），
需结合企业层级/跨区域属性判断，属专业直派规则的细化方向，不作为已解决能力宣称。

### 实现规则：三层决策

```
① 属地主办（89% 情形）
   诉求地点 → 属地区划识别（镜湖/弋江/鸠江/湾沚/繁昌/南陵/无为/经开区/三山/高新区）
   → 主办：属地区县政府 / 开发区管委会
② 专业直派（11% 情形）
   行业性极强的诉求 → 市直部门或专业机构
   （实测案例：公交线路→市公安局+芜湖公交公司；消费投诉→12315 中心）
③ 抄送协调（规范要求）
   直派部门时，同步抄送属地热线主管部门督促协调
```

### 输出（每次派单给出完整决策包）
- **主办单位**：属地政府/开发区（附依据：属地管理原则 + 历史同类工单实际承办单位）
- **业务指导/协办单位**：对应市直主管部门（附依据：部门职责条款）
- **争议点提示**：职责交叉时标注"主办+协办组合、可能的退回风险、建议提前协调"
- **专业直派例外**：命中行业性诉求时直接给专业承办单位并说明理由
- **置信度 + 人工复核提示**

### 可验证指标
主承办单位命中率（与官方样例实际承办单位一致性）：**94.4%**（对比通用做法 5.6%）。

## 四、支柱二：急件识别与办理时限分级（办得快）

### 业务痛点
安全隐患类诉求（燃气泄漏、井盖缺失、消防通道堵塞、危房、电线坠落、大面积停水停电）若被当作一般件排队，后果不可逆。

### 政策依据（同上规范）
- 对**大面积停水停电、环境污染等紧急事项**，承办单位需**第一时间处置并在 24 小时内反馈进展**；
- 一般性诉求在规定时限内办结；确因客观原因可申请延期或「**承诺办理**」（复杂事项不超过 9 个月）。

### 实现
风险识别（安全隐患 / 人身安全 / 公共设施故障 / 环境污染 / 群体性影响）→ 输出：

| 等级 | 触发 | 建议动作 |
|---|---|---|
| **特急** | 燃气泄漏、电线坠落、井盖缺失致伤风险、消防通道堵塞、危房 | 30 分钟内电话通知承办单位 + 立即派件 + 24 小时内反馈进展（规范时限） |
| **紧急** | 大面积停水停电、环境污染、道路塌陷 | 当日派件 + 24 小时内反馈进展 |
| **一般** | 咨询、建议、非安全类投诉 | 规定时限内办结；复杂事项可建议"承诺办理" |

### 可验证指标
安全隐患类诉求识别召回率（官方样例 `urgent` 标记 4/18 + 构造安全隐患案例集）。

## 五、支柱三：诉求治理（治得久）——从办单到治事

### 业务痛点
热线真正的治理价值不在"办完一单"，而在发现"这件事反复发生/多人在说"，及时并案与督办。

### 政策依据（同上规范）
- 对**群众多次反映、承办单位办理不到位**的问题，热线联合政府督查机构开展专项督办；
- 对未解决或不满意的合理诉求启动人工回访并**再次交办**；**两次以上不满意**事项需分管负责同志审签；
- 承办单位**不得随意退回**工单。

### 实现三条治理能力
1. **并案与聚集预警**：同点位（地点线索匹配）+ 同类别 + 时间窗（7 日）内 ≥3 件 → 建议并案核查、提示群体性诉求，转"未诉先办"主动治理；
2. **重复诉求督办提示**：识别"再次反映/多次反映"（样例中 2/18 即属此类）→ 提示督办风险与升级路径；
3. **退回风险预判**：职责交叉/权责不清的工单，提前标注"可能被退回，建议派前协调"，对应规范"不得随意退回 / 3 次交办指定承办"条款。

### 可验证指标
聚集发现（构造同点位 3 件案例）+ 重复诉求识别（样例 repeat_request 2/18 召回）。

## 六、贯穿能力：依据链可追溯 + 双模型交叉复核（信得过）

**政策依据**：规范明确"答复环节要求承办单位**必须正面回应诉求，列明政策依据和处理过程**，经热线审核不规范的将退回重办"。

**我们的做法**：
- **依据链可展开**：每个结论（类别、主办单位、时限等级、答复内容）都可展开查看——政策条款原文、部门职责条目、历史同类工单的实际承办单位、置信度；
- **双模型交叉复核**：主判模型（deepseek-v4-pro）+ 复核模型（qwen-plus-latest）独立判断，分歧 → 标记"需人工判断"并展示两个结论；复核拦截记录作为技术亮点数据；
- **防幻觉三道闸**：政策引用 QC 校验（不在库中的引用标警）、转写原文证据保全、LLM 降噪"事实逐字保留 + 过度删改自动回退"。

这是 15% 技术性 + 10% 合规性的主要抓手，也是"政务 AI 敢不敢用"的关键。

## 七、与通用做法的对照（PPT 杀手页，建议单独一页）

同一案例（烧烤店占道经营 + 油烟噪音），两种系统的输出对比：

| 维度 | 通用单链 LLM | 本方案 |
|---|---|---|
| 类别 | 城市管理 | 城市管理（置信度 0.62，候选含生态环境 0.28） |
| 主办单位 | "建议转城市管理局" | **鸠江区政府**（依据：属地管理原则；历史同类工单 89% 由属地承办） |
| 协办/指导 | 无 | 市城市管理局（占道经营职责）、市生态环境局（油烟） |
| 争议与风险 | 无 | ⚠ 职责交叉：主办+协办组合，标注退回风险与建议协调方式 |
| 紧急度 | 无 | 一般件（无安全隐患特征） |
| 时限建议 | 无 | 规定时限内办结（依据：规范一般件条款） |
| 依据链 | 无 | 可展开：政策条款 / 部门职责 / 历史案例 |
| 治理视角 | 无 | 该点位 7 日内第 3 次同类投诉 → 建议并案 + 未诉先办预警 |

**核心差异一句话：通用做法输出"一段文字"，我们输出"一个可执行、可追溯、可解释的派单决策"。**

## 十、取舍（3.5 周内做什么、不做什么）

**必做（保 8 项功能 + 三支柱）**
1. 五节点主链路在平台跑通（理解/工单/分类/派单/答复）
2. 属地识别 + 三层派单规则 + 依据链（支柱一）
3. 急件分级与时限建议（支柱二）
4. 职责交叉与信息不足提示（必展示第 8 项）
5. 人工审核修改闭环
6. 两个案例（城市管理 + 公共安全/其他类型）

**加分（时间够再做）**
7. 聚集/并案预警与重复诉求督办提示（支柱三）
8. 双模型交叉复核
9. 外接完整审核工作台（提升体验分）

**不做（避免分散）**
- 不做语音合成的回访外呼（无必要，且有合规风险）
- 不做自动派单（规范与合规都要求人工确认，绝不越界）
- 不追求覆盖全部 12 大类的细分类目（用知识库+检索泛化，不硬编码）
